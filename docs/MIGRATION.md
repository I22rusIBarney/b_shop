# Переезд с RWP Shop на BobrGO Shop

Новый бот ставится на **отдельный VPS** и со старым никак не связан: базу RWP он получает файлом.
Клиенты со способами входа, тарифы (в том числе скрытые), подписки, платежи, сохранённые карты/СБП, промокоды
(в том числе открывающие скрытые тарифы, и кому они уже открыты), рефералы с бонусами, имена устройств, FAQ и обращения
переносятся из админки: **Настройки → Перенос из RWP**. Пользователи в Remnawave не трогаются: подписки работают,
ссылки у клиентов остаются прежними.

Что **не переносится** и настраивается в админке руками:
- ключи ЮKassa, «Мой налог», SMTP, Яндекс ID / VK ID;
- тексты бота (`translations`): у нас свои тексты;
- Web Push (VAPID): уведомления идут в Telegram и на почту;
- рулетка, мини-игры, партнёрка, «купить другому», промокоды на трафик — этих функций нет.

## 1. Выгрузка базы старого бота

На сервере RWP (бот можно не останавливать):

```bash
cd ~/remnawave-telegram-shop
DB=$(docker compose ps --services | grep -iE 'db|postgres' | head -1)
docker compose exec -T $DB sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > ~/rwp.dump
ls -lh ~/rwp.dump
```

Скачайте `rwp.dump` к себе (WinSCP, FileZilla, `scp`). Подойдёт и SQL-выгрузка, и архив `.gz` / `.tar.gz` с ней.

## 2. Пробный перенос (сколько угодно раз)

Админка нового бота → **Перенос из RWP** → «Выбрать файл». Бот загрузит файл частями, восстановит его во временную
базу и покажет, что будет перенесено, — пока вы не нажмёте «Перенести», ничего не меняется.
Если в новом боте уже есть клиенты (после тестов), включите «Заменить текущие данные»: клиенты с подписками и платежами,
тарифы, промокоды и FAQ удалятся и придут из файла заново. Настройки, оформление, автоматизации и рассылки останутся,
вы останетесь в админке.

После переноса бот сам обновит подписки из панели Remnawave (короткие ID, ссылки, сроки).

## 3. Настоящий переезд

1. Заполните в новом боте «Оплата и ЮKassa», «Мой налог», «Вход и почта». Проверьте тарифы после пробного переноса.
2. Остановите старый бот (его базу не удаляйте — это резервная копия):
   ```bash
   cd ~/remnawave-telegram-shop && docker compose stop $(docker compose ps --services | grep -viE 'db|postgres')
   ```
3. Сделайте свежую выгрузку (шаг 1) и перенесите её (шаг 2, с «Заменить текущие данные»).
4. Запустите новый бот с **тем же** `BOT_TOKEN` — клиенты ничего не заметят.
5. **ЮKassa** → Интеграция → HTTP-уведомления: `https://<домен нового бота>/api/webhooks/yookassa`.
   Сохранённые карты/СБП продолжают работать: они привязаны к магазину ЮKassa, а не к боту.
6. **Remnawave**: «Вебхуки Remnawave» → «Сгенерировать», сохраните и впишите строки из подсказки в `.env` панели
   (секрет новый). Перезапустите панель.
7. **Яндекс ID / VK ID**: замените адрес возврата на новый домен. Если меняется домен веб-приложения — обновите его в @BotFather.

## 4. Проверка

- Статистика → Обзор: число клиентов и доход за всё время совпадают с RWP.
- Карточки пары клиентов: подписки, платежи, устройства, реферер, открытые скрытые тарифы.
- Тестовая покупка на минимальный тариф и чек в «Мой налог».
- Вебхуки Remnawave → Журнал: через несколько минут там появятся события от панели.

Откат: `docker compose start` в папке старого бота — его база не изменялась.

## Без админки (командой)

То же самое умеет команда в контейнере, если базу RWP восстановить на сервер нового бота как `rwp_import`:

```bash
docker compose exec -T db sh -c 'createdb -U "$POSTGRES_USER" rwp_import'
docker compose exec -T db sh -c 'pg_restore -U "$POSTGRES_USER" -d rwp_import --no-owner --no-privileges' < ~/rwp.dump
docker compose run --rm shop import-rwp --dry-run --from "postgres://ПОЛЬЗОВАТЕЛЬ:ПАРОЛЬ@db:5432/rwp_import?sslmode=disable"
```

Без `--dry-run` — настоящий перенос; `--bot <id>` — только один бот из многоботовой базы; `--force` — в непустую базу.
