# Переезд с RWP Shop на BobrGO Shop

Клиенты, подписки, платежи, сохранённые карты/СБП, промокоды, рефералы, имена устройств, FAQ и обращения
переносятся командой `import-rwp`. Пользователи в Remnawave не трогаются: подписки продолжают работать,
ссылки у клиентов остаются прежними. Сначала делаем пробный прогон на тестовом стенде, потом — настоящий переезд.

Что **не переносится** и настраивается в админке руками:
- ключи ЮKassa, «Мой налог», SMTP, Яндекс ID / VK ID (секреты RWP хранит у себя, переносить их через выгрузку незачем);
- тексты бота (`translations`): у нас свои тексты, приветствие задаётся в админке;
- Web Push (VAPID): уведомления идут в Telegram и на почту, push-подписки не нужны;
- рулетка, мини-игры, партнёрка, «купить другому», промокоды «открыть тариф» — этих функций нет.

## 1. Пробный прогон (тестовый стенд)

На сервере с RWP снимаем копию базы (бот при этом работает, копия согласованная):

```bash
cd ~/remnawave-telegram-shop
DB=$(docker compose ps --services | grep -iE 'db|postgres' | head -1)
docker compose exec -T $DB sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > ~/rwp.dump
ls -lh ~/rwp.dump
```

На сервере с новым ботом (в папке с `docker-compose.yaml` BobrGO Shop) поднимаем копию как отдельную базу `rwp_import`:

```bash
docker compose exec -T db sh -c 'createdb -U "$POSTGRES_USER" rwp_import'
docker compose exec -T db sh -c 'pg_restore -U "$POSTGRES_USER" -d rwp_import --no-owner --no-privileges' < ~/rwp.dump
```

Пробный прогон — ничего не записывает, только показывает отчёт:

```bash
docker compose run --rm shop import-rwp --dry-run \
  --from "postgres://$(grep ^POSTGRES_USER .env | cut -d= -f2):$(grep ^POSTGRES_PASSWORD .env | cut -d= -f2)@db:5432/rwp_import?sslmode=disable"
```

В отчёте смотрим разделы «Незнакомые значения» и «Предупреждения». Если в RWP несколько ботов (таблица `bot`),
переносим только основной: `--bot <id>`.

## 2. Настоящий переезд

1. В админке нового бота заполните «Оплата и ЮKassa», «Мой налог», «Вход и почта», тарифы проверьте после импорта.
2. Остановите старый бот (базу RWP не удаляйте — пусть лежит как резервная копия):
   ```bash
   cd ~/remnawave-telegram-shop && docker compose stop $(docker compose ps --services | grep -viE 'db|postgres')
   ```
3. Снимите свежую копию базы и восстановите её в `rwp_import`, как в шаге 1 (старую `rwp_import` перед этим удалите:
   `docker compose exec -T db sh -c 'dropdb -U "$POSTGRES_USER" rwp_import'`).
4. Импорт без `--dry-run`. После переноса команда сама обновит подписки из панели Remnawave (короткие ID, ссылки, сроки):
   ```bash
   docker compose run --rm shop import-rwp --from "postgres://…@db:5432/rwp_import?sslmode=disable"
   ```
   Импорт идёт в чистую базу: если в новой базе уже есть клиенты (например, после тестов), команда откажется.
   Очистить тестовые данные: `docker compose down -v` и заново `docker compose up -d` (база создастся пустой).
5. Запустите новый бот с **тем же** `BOT_TOKEN` — клиенты ничего не заметят: `docker compose up -d`.
6. **ЮKassa** → Интеграция → HTTP-уведомления: адрес `https://<ваш домен>/api/webhooks/yookassa`.
   Сохранённые карты/СБП продолжают работать: они привязаны к магазину ЮKassa, а не к боту.
7. **Remnawave**: в админке «Вебхуки Remnawave» нажмите «Сгенерировать», сохраните и впишите три строки из подсказки
   в `.env` панели (секрет — новый, старый от RWP больше не используйте). Перезапустите панель.
8. **Яндекс ID / VK ID**: в кабинетах разработчика замените адрес возврата на новый домен.
9. Если меняется домен веб-приложения — обновите его в @BotFather (Menu Button / Web App).

## 3. Проверка после переезда

- Статистика → Обзор: число клиентов и доход за всё время совпадают с RWP.
- Откройте карточку пары клиентов: подписки, платежи, устройства, реферер.
- Сделайте тестовую покупку на минимальный тариф и проверьте чек в «Мой налог».
- Вебхуки Remnawave → Журнал: через несколько минут там появятся события от панели.

Если что-то пошло не так, старый бот поднимается обратно одной командой (`docker compose start` в его папке),
его база не изменялась.
