# BobrGO Shop

Telegram-бот и веб-кабинет (Mini App + сайт) для продажи VPN-подписок на панели **Remnawave**:
тарифы, оплата ЮKassa (СБП, карты, автопродление), чеки «Мой налог», промокоды и скрытые тарифы, рефералка,
поддержка с ИИ-ассистентом, рассылки, автоматизации, статистика и перенос клиентов из RWP Shop.
Всё, кроме самого запуска, настраивается в админке.

## Установка за 5 минут

### Что понадобится

| | |
|---|---|
| **Сервер** | VPS с Ubuntu 22.04/24.04 или Debian 12, от 1 ГБ памяти. Лучше отдельный, не тот, где панель |
| **Домен** | например `shop.bobrgo.com`, A-запись на IP сервера (в Cloudflare — серое облако) |
| **Бот** | токен из [@BotFather](https://t.me/BotFather) |
| **Ваш Telegram ID** | узнать у [@userinfobot](https://t.me/userinfobot) |
| **Панель** | адрес панели Remnawave и API-токен: панель → Настройки → API-токены → создать |

### Команда

Зайдите на сервер под root и выполните:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/I22rusIBarney/b_shop/main/install.sh)
```

Нужен токен GitHub: github.com → Settings → Developer settings → Personal access tokens → **Tokens (classic)**,
галочки `repo` и `read:packages`.

```bash
export GH_TOKEN=ghp_ваш_токен
bash <(curl -fsSL -H "Authorization: token $GH_TOKEN" https://raw.githubusercontent.com/I22rusIBarney/b_shop/main/install.sh)
```

Скрипт задаст вопросы — домен, токен бота, ID админов, адрес и токен панели, почту для сертификата — и **проверит
каждый ответ**: смотрит ли домен на сервер, принимает ли Telegram токен, пускает ли панель. Дальше всё сам:
ставит Docker, генерирует пароль базы и ключ шифрования, выпускает HTTPS-сертификат, запускает бота
и включает ежедневные резервные копии. В конце покажет адрес админки и что сделать дальше.

### HTTPS и nginx

Ничего настраивать руками не нужно, скрипт выбирает сам:

| Что на сервере | Что делает скрипт |
|---|---|
| Порты 80/443 свободны (отдельный VPS) | Запускает свой **Caddy** в отдельном контейнере: сертификат Let's Encrypt выпускается и продлевается сам |
| Стоит обычный **nginx** (apt) | Создаёт **отдельный файл** `/etc/nginx/sites-available/bshop.conf` и выпускает сертификат через certbot. Другие сайты не трогаются |
| Порты заняты чем-то другим (например, nginx панели Remnawave в Docker) | Ничего не меняет, показывает готовый блок `server { … }` для вашего прокси. Бот слушает `127.0.0.1:8080` |

Панель и её nginx установщик **никогда не правит**. Поэтому проще всего ставить бота на отдельный сервер.

### После установки (в админке)

Откройте `https://ваш-домен`, войдите через Telegram с аккаунта админа.

1. **Настройки → Оплата и ЮKassa** — Shop ID и секретный ключ. В личном кабинете ЮKassa → Интеграция →
   HTTP-уведомления укажите `https://ваш-домен/api/webhooks/yookassa`.
2. **Тарифы** — создайте тарифы или перенесите из RWP (п. 4).
3. **Настройки → Вебхуки Remnawave** — «Сгенерировать», затем три строки из подсказки в `.env` панели
   (уведомления клиентам об окончании подписки и трафике, вам — о падении нод).
4. **Настройки → Перенос из RWP** — загрузите выгрузку базы старого бота, см. [docs/MIGRATION.md](docs/MIGRATION.md).
5. По желанию: «Мой налог», почта и вход через Яндекс/VK, поддержка и ИИ, автоматизации.

Кнопка «Открыть» в меню бота настраивается автоматически. Чтобы вход через Telegram работал и в обычном браузере
(иначе на странице входа будет «Bot domain invalid»), один раз отправьте @BotFather команду `/setdomain`, выберите бота и укажите ваш домен.

Клиенты, которые уже есть в панели, подтягиваются кнопкой **Клиенты → «Синхронизировать с панелью»**: подписки привязываются
к клиентам по Telegram ID или почте, тариф — по тегу пользователя в панели.

## Управление

На сервере появляется команда `bshop`:

| Команда | Что делает |
|---|---|
| `bshop status` | состояние |
| `bshop logs` | журнал бота (`bshop logs caddy` — сертификаты), Ctrl+C — выход |
| `bshop update` | копия базы → новая версия → перезапуск |
| `bshop restart` | перезапуск |
| `bshop backup` | копия базы сейчас |
| `bshop restore ФАЙЛ` | вернуть базу из копии |
| `bshop env` | поправить `.env` (токены, домен) и перезапустить |
| `bshop uninstall` | удалить (копия базы останется) |

Повторный запуск установщика тоже работает: предложит обновиться или пройти настройку заново
(пароль базы и ключ шифрования сохранятся).

**Резервные копии** делаются каждую ночь в `/opt/bshop/backups` (база и `.env`), хранятся 14 дней.
Ключ `SECRET_KEY` из `/opt/bshop/.env` сохраните отдельно: без него не расшифровать ключи ЮKassa и другие секреты в базе.

**Обновления**: при каждом изменении кода GitHub сам собирает Docker-образ (`ghcr.io/i22rusibarney/b_shop`),
поэтому `bshop update` просто скачивает его. Сервер ничего не компилирует. Миграции базы применяются при запуске.

## Ручная установка (без скрипта)

```bash
git clone https://github.com/I22rusIBarney/b_shop /opt/bshop && cd /opt/bshop
cp .env.sample .env && nano .env            # заполнить
cp Caddyfile.example Caddyfile              # если HTTPS делает встроенный Caddy
docker compose up -d                         # или up -d --build, чтобы собрать образ на сервере
```

## Устройство

- Go (сервер, бот, API) + React/TypeScript (кабинет и админка), PostgreSQL. Всё в одном контейнере `shop`.
- `.env` — только то, без чего не запуститься. Остальные настройки — в базе, секреты зашифрованы (AES-256-GCM).
- Спецификация функций — [docs/SPEC.md](docs/SPEC.md), переезд с RWP — [docs/MIGRATION.md](docs/MIGRATION.md).

## Разработка

```bash
TEST_DATABASE_URL=postgres://bshop:bshop@127.0.0.1:5432/bshop_test?sslmode=disable go test ./...
cd web && npm ci && npx vite build && cd ..
DEV=true DATABASE_URL=… PUBLIC_URL=http://localhost:8080 SECRET_KEY=… go run ./cmd/bshop
```
